# Tinni Star

Tinni Star is a new, separate Flutter social voice-room application inside this repository.

It does **not** replace or modify the existing `apps/mobile` voice-chat demo and it does not modify Anamika's existing code.

## Current build

- App path: `apps/tinni_star/`
- Android application ID generated by CI: `com.tinnistar.tinni_star`
- Minimum Android SDK in CI: 24
- Independent workflow: `.github/workflows/tinni-star-build.yml`
- Artifact: `tinni-star-debug-apk`

## Anamika connector boundary

Tinni Star receives connector links in this form:

```text
tinnistar://anamika?token=<PAIRING_TOKEN>&command=<URL_ENCODED_JSON>
```

Supported command JSON types:

```json
{"type":"diagnostics"}
{"type":"rollback"}
{"type":"apply_pack","pack":{...}}
```

A Function Pack is accepted only when:

1. the per-install pairing token matches,
2. its app schema range is compatible,
3. its version is valid/newer for normal apply,
4. its HMAC signature matches the canonical pack payload,
5. its runtime configuration passes validation.

Accepted packs are persisted. The previous pack is retained for rollback.

## Hot-fix boundary

Function Packs intentionally update **compatible runtime behavior**, not arbitrary compiled Dart/native code. They can safely change supported room rules, seat/mic modes, feature flags, gift limits and other declared runtime parameters without reinstalling the full APK.

A change to compiled Flutter/Dart code, the Android manifest, native SDK binaries, signing keys or a provider SDK itself still requires a normal app build/update. Tinni Star reports that boundary rather than pretending an unsafe code injection is a normal hot fix.

## External provider integration

The architecture has replaceable adapters for RTC, IM, billing, push, analytics, crash reporting, remote config and visual-effect engines. The repository uses local functional adapters where provider credentials/server infrastructure are not available.

Real production connectivity requires provider-side material such as:

- RTC App ID/token service
- IM SDK App ID/user signature service
- production REST/WebSocket backend
- Google Play product configuration + server receipt verification
- push/analytics/crash/remote-config project configuration
- actual SVGA/PAG/MP4/GIF assets

These are provider/backend dependencies, not missing UI architecture.

See `docs/BLUEPRINT_STATUS.md` for the module-by-module map.
